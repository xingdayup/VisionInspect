# 批量质检与证据复核业务规格

本规格已由用户确认，实施目标为单图与批量检测、Agent 多步复核、逐项人工处理和报告归档。当前为研究工作台，不连接产线放行。

## 工作流

1. 单图或网页多图上传，每批最多 100 张，同一批次使用相同类别、模型和策略快照。单文件最多 10 MiB、1600 万像素。
2. 图片质量检查通过后执行已冻结的 PatchCore。明确正常和明确异常直接按原策略生成候选结论。
3. 不确定区间样本进入 LangGraph 复核。Agent 根据当前证据选择查看局部、切换正常参考或结束，每图模型调用最多 3 次，包含重试。
4. 复核通过需要有效正常参考、全部疑似区域已做局部检查、证据一致且无可见异常。遗漏、错误、矛盾、不确定均转人工。
5. 人工逐项记录结论和说明。原始检测、Agent 判断和人工记录分开保存，人工记录只追加。
6. 导出单图 JSON、批次 JSON/CSV，显示结论来源、完整证据和调用轨迹。

## 批次行为

- 上传先建草稿，再逐文件上传；各文件独立校验，错误可见，成功项可继续启动。
- 串行调度，全局待执行上限 200。暂停与取消在当前图片完成后生效。
- 失败项重试生成关联新任务，原任务保留。重启保留队列与批次，执行中断项失败，相关批次暂停等待继续。
- 汇总区分正常候选、异常候选、待人工、失败、取消、已人工复核，不将候选比例称为产品合格率。

## 技术与边界

- FastAPI、SQLite、React 保留；新工作流名为 `agent_review`，旧 baseline/fixed/dynamic 兼容。
- LangGraph 管理循环，vLLM 0.27.1 承载 Qwen3-VL-8B-Instruct BF16；不另加载规划模型。
- 整套部署在 PAI。应用独立环境，平台 vLLM 运行时只读复用，不安装到系统 Python。
- 检测 CPU worker 和 GPU 服务独立 TTL 600 秒。模型冷启动最多 300 秒，单图执行最多 180 秒，模型请求最多 45 秒。
- 当前仅 bottle 有完整模型。没有真实产品规范，以视觉证据和正常训练参考进行研究复核，不推断尺寸公差、成因或工业放行。
- 已见测试图只做工程回归。新复核策略的误报漏报收益必须用独立标注数据验证。
