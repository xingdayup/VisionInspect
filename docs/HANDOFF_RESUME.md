## 1. 一句话定位

一个面向工业视觉质检的研究原型：用单类异常检测（PatchCore）先判，只把落在"校准不确定区间"内的少数样本交给本地视觉语言模型（Qwen3-VL-8B）做有界证据复核，复核结论必须通过确定性门控才会生效，其余转人工。

技术关键词：PatchCore / CUDA / LangGraph 有界循环 / vLLM / Qwen3-VL / 证据绑定校验 / 确定性门控 / FastAPI + React 工作台。

## 3. 系统做了什么

```
上传图像
  → 质量门（清晰度/亮度）
  → PatchCore 打分（CUDA）
      ├─ 分数 > 阈值                → anomaly_candidate（不进复核）
      ├─ 分数 < 复核区间下界         → normal_candidate（不进复核）
      └─ 分数落在 [8.8237, 9.6100]  → 进入 VLM 复核（83 张里只有 4 张）
  → LangGraph 有界复核循环（最多 8 次模型调用）
      baseline → decide → tool → decide → … → finish
  → 确定性门控
      ├─ 全部通过 → normal_candidate / anomaly_candidate
      └─ 任一不过 → manual_review（附机器可读的拒绝原因）
  → 报告 + 证据 + 轨迹落盘（可回查每一轮送给模型的图）
```

前端是 React + TypeScript 工作台，后端 FastAPI + SQLite（schema 3），支持单图与批次、证据查看、人工复核、历史与导出。

## 4. 我做了什么

按四个层面写，简历里可以挑其中两三个展开。

**一、把检测器迁移到 GPU 并重新校准。** PatchCore 的参数、特征、memory bank、近邻与异常图计算全部搬到 CUDA FP32，无 CUDA 时明确失败而不是悄悄降级；图像解码与文件校验仍留在 CPU。历史 checkpoint 先在主机内存安全读取再严格加载到 CUDA，不改模型、预处理与冻结阈值。

**二、设计并实现有界证据复核循环。** 用 LangGraph 组织 `baseline / decide / tool / finish` 四个节点。模型每一轮只能做一个动作（看某个区域、换参考图、结束），必须返回结构化 JSON，观察必须引用本轮实际提供的证据 id。

**三、把"模型说什么"和"系统认不认"分开。** 这是全项目最核心的设计：模型只提供观察，最终状态由确定性门控计算。为 `normal` 结论设了六道闸（区域未核查、提取被截断、异常观察冲突、无正常依据、参考相似度不足、分数高于区间上界），任一不过就转人工。

**四、工程化与真机验收。** 引入 ruff + prettier + tsc 的 CI；格式化 53 个 Python 文件；包内 152 个函数的返回标注从 8% 提到 100%，docstring 从 3% 提到 81%；写单一部署入口 `deploy_fresh_gpu.sh`；在真机上完成 CUDA、vLLM、双进程 TTL 与内存监管的验收。

## 5. 量化结果

### 5.1 工程与性能

| 指标 | 值 | 说明 |
| --- | --- | --- |
| 单图推理 | **13.7 ms**（GPU） vs 42.4 ms（CPU） | 约 3 倍 |
| 拟合 168 张 | 18.9 s | GPU 版 |
| 校准 41 张 | 12.7 s | 只用正常验证图，不碰测试集 |
| 评估 83 张 | 21.4 s | GPU 版 |
| 测试通过 | **166 passed / 1 skipped** | 跳过项需真实 CUDA 断言 |
| 真机验收 | `passed: true`, `full_agent_loop_exercised: true` | 2026-10-22 AutoDL |

### 5.2 检测精度（83 张测试集，GPU 拟合的 checkpoint）

image AUROC **1.000**、image F1 **0.9844**、pixel AUROC **0.9781**、AUPRO **0.9181**。

> 注意：这是单类别、83 张的测试集，不能外推为"通用精度"。见第 8 节。

### 5.3 复核的效果（区间内 4 张）

| 指标 | 无复核 | 有复核 |
| --- | ---: | ---: |
| 误报落到用户手里 | 2 | **0** |
| 自动给出的结论 | 83 | 80 |
| 其中正确 | 80 | —— |
| 平均单张复核耗时 | —— | 约 43–51 s / 5–6 次模型调用 |

区间内 **3/4 自动给出正确结论，1/4 因真实不可判读转人工，零假阳性**。

### 5.4 安全护栏的效果（区间外强制复核 24 张，实验开关，生产不启用）

| 真值 | 项 | 护栏前 | 护栏后 |
| --- | --- | ---: | ---: |
| 缺陷 10 张 | 被判成正常（漏检） | **6** | **0** |
| 缺陷 10 张 | 转人工 | 3 | 8 |
| 正常 14 张 | 误报 | 1 | **0** |

结论：复核只能在**校准过的区间内**下调检测器的判断；区间外必须禁止给出 normal。这条规则的代价是人工从 6 张涨到 13 张，在质检场景是正确取舍。

### 5.5 一个反直觉的机制发现（可作亮点）

对 8 张已知正常图的 11 个区域做两次独立判断：孤立判断的假阳性率 **9.1%**；但把"该区域存在纹理差异"这一既有结论注入上下文后，**45.5%（5/11）的判断被翻转**。

修复方式是上下文只提供已查看区域的 **id 列表**，不再回灌历史结论，也不给 `reviewed_regions` 的结论值。修复后同一批图从 1/4 可判变为 **3/4 可判、零假阳性**。

> 这条的价值在于：它把"模型能力不足"这个模糊归因，换成了一个可测量、可修复的机制（上下文自强化）。

### 5.6 证据视图 2×2 对照（真机，最新一轮）

同一批 4 张区间内图、同一 checkpoint、同一提示词，只改**证据像素**。四组各跑一次，约 5 分钟一组：

| 组 | 发送上限 | 热图+候选框 | 自动下结论 | 正确 | 转人工 | 拒绝门控 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| A 生产默认 | 512 | 否 | **3/4** | 3 | 1 | `no_final_decision` |
| D | 1024 | 否 | **3/4** | 3 | 1 | 同上（逐图相同） |
| B | 512 | 是 | 1/4 | 1 | 3 | `anomaly_conflict`, `no_final_decision` |
| C | 1024 | 是 | 2/4 | 2 | 2 | 同上 |

两个结论，都推翻了实验前的假设：

1. **提高发送上限无效。** A 与 D 逐图、逐门控完全一致。原因：区域裁剪本来就按原图像素切，只有整体视图会受上限影响；而整体视图不是瓶颈。实际最小的区域原生只有 **39×42 像素**，512 与 1024 对它没有任何区别。
2. **把热图画到证据上是净负改动。** 模型把 `inferno` 的橙黄色读成瓶内壁缺陷，第一轮原话："original 中 R1 区域有**明显污渍和不均匀反光**"、"original 内部有**明显浑浊/沉淀物**"。局部裁剪随后显示正常，于是 `anomaly_conflict` 把图推给人工。

> 机制与 5.5 的锚定效应同源：任何"这里有异常"的暗示都会把模型推向 anomaly。文字回灌历史结论翻转 5/11，像素叠加缺陷色彩则直接**伪造**了一个不存在的缺陷。这说明热图不是可复核的证据，而是检测器自己的意见。

### 5.7 四个被数据否掉的优化

| 尝试 | 孤立测量（看起来有希望） | 接进真实循环 | 决定 |
| --- | --- | --- | --- |
| 双参考局部视图 | unclear 3/11 → **0/11** | **0/4 可判**（单参考 3/4） | 回退，默认关闭 |
| unclear 区域补查 | —— | 补到 6 次调用仍 unclear，且区域级判断在轮次间漂移 | 默认关闭 |
| 发送上限 512 → 1024 | —— | 与 512 逐图完全相同 | 无效 |
| 热图 + 候选框标注 | —— | 3/4 → 1/4 | 净负，默认关闭 |

四个都保留了代码路径并默认关闭，否定结论写进文档。这组数据也解释了为什么生产默认配置（512、无标注、单参考）是四种里最好的——它不是拍脑袋选的，是对照出来的。

## 6. 四个可以展开的技术故事

面试时按"问题 → 测量 → 改动 → 结果"讲，每个都有数据支撑。

**故事 1：复核循环自己把自己卡死。**
现象：4 张图全部失败。逐轮拆开后发现失败点全在确定性门控或协议上，没有一张是"看不清"：模型重复请求已看视图会直接终止循环；预算 5 次在数学上不够（1 整体 + 4 区域 + 1 结束 = 6）；参考相似度下限卡在 1e-4 的噪声量级。改法是给重复视图一次纠正调用、预算提到 8、相似度改绝对下限 0.99。

**故事 2：45.5% 的锚定效应。**
见 5.5。关键是把"为什么同一批图时而全 normal 时而全 anomaly"这个玄学问题，变成两个可重复的对照实验。

**故事 3：安全护栏。**
把复核范围放宽到区间外做测量，发现 10 张细微缺陷里 6 张会被判成正常。于是加规则：分数高于复核上界时禁止 normal。漏检 6 → 0。

**故事 4：四次被数据否掉的优化。**
四个"看起来该更好"的改动，全部在真实循环里被推翻，数字见 5.7：双参考视图（孤立测量 unclear 3/11→0/11，接进循环 0/4 可判）、unclear 区域补查（6 次调用仍 unclear）、发送上限 512→1024（逐图完全相同）、热图与候选框标注（3/4 → 1/4，且模型把热图读成"瓶内壁污渍"，伪造出缺陷）。

四个改动都保留代码路径、默认关闭，否定结论写进文档。完整 2×2 见 5.6。

> 这个故事体现的是**不迷信孤立指标、坚持在真实循环里复测**的方法论。最能说明问题的是双参考：孤立场景下它把 unclear 清零，进了真实循环却一张都判不出来——因为局部视图删掉待检原图后，模型仍按协议引用 `original`，被证据校验拒绝。

## 9. 面试可能追问，及诚实答案

**Q：为什么要"单类检测 + VLM 复核"两层，不直接端到端用 VLM？**
A：单类检测器只在正常样本上建 memory bank，对纹理级差异更敏感、单图 13.7 ms；VLM 强在语义与可解释，但对细粒度纹理判别弱、单次 40 s 级。分层是让便宜的做筛、贵的做复核。

**Q：复核到底带来了什么收益？**
A：区间内误报 2 → 0，代价是自动结论从 83 降到 80、单张多花约 45 秒。它不能减少漏报——检测器没见过的缺陷形态，复核救不回来，这一点是结构性限制。

**Q：怎么保证 VLM 不瞎编？**
A：三层：结构化输出 + 证据 id 绑定（引用本轮没提供的图片会被直接拒绝）、确定性门控、以及机器可读的拒绝原因码，事后可按原因分组统计。

**Q：样本这么小，结论可信吗？**
A：区间内只有 4 张，所以只做定性判断，不做百分比提升的宣称；机制类的结论（如 45.5% 锚定翻转）用 11 个区域的独立对照支撑。这是我在文档里明确标注的限制。

**Q：这个项目最难的部分是什么？**
A：不是模型，是判定权归属。让模型说"正常"很容易，难的是设计一套规则，使得模型只有在证据完整、无冲突、且检测分数落在校准区间内时，才有资格把结论改判。

## 12. 一句话总结（可直接用于简历开头）

> 用单类异常检测筛出可疑样本，再让本地视觉语言模型在**有界证据**上复核，但把最终判定权留在确定性规则手里——在 83 张测试集上把误报从 2 降到 0，并明确划出了"复核只在校准区间内可信"的安全边界。
